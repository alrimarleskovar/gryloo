## Implementation

The shared semantic graph uses the existing `asset.bridge`, `asset.swap.exact-input` and `asset.liquidity.uniswap-v3` actions with one pure `asset.liquidity.prepare` computation node. Bridge `amount-out` feeds preparation. The preparation propagates the actual reconciled destination USDC into the selected partial swap amount and USDC reserved for liquidity. A favorable settlement above the quote estimate is accepted within the authorized source ceiling and triggers refreshed destination review; an amount above that ceiling is rejected. The independently reconciled swap WETH feeds the mint. An explicit no-swap graph uses a USDC-only range. Chat and canvas dispatch the same typed authoring command and yield the same IR. The existing canvas renders the typed edges, inspector edits the composition, and the Review disclosure gives a human-readable full-flow summary.

The existing Uniswap v3 liquidity compiler/encoder has Base and Arbitrum deployment configuration. Its pool state validation retains the Base default and pins the Arbitrum factory, position manager, token0 WETH, token1 native USDC, 0.05% pool, fee tier 500 and tick spacing 10. The read-only Arbitrum service resolves the pool via factory `getPool` at one canonical block, checks deployed code, pool/manager factory and manager WETH, token order, fee, tick spacing, slot state and freshness. It fails closed on a mismatch. No separate Arbitrum liquidity implementation or new protocol was added.

The split planner uses observed sqrt price and selected ticks in integer Uniswap v3 range math, not a generic 50/50 allocation. It handles in-range partial USDC swap and out-of-range one-sided positions. It uses actual reconciled bridge amount, checks independent Arbitrum ETH gas reserve, source and destination spend ceilings, and recalculates mint bounds only after a reconciled swap output. The canonical artifact set, simulation, policy, refreshed destination Manifest and execution plan bind provider/route, target/function, recipient, chains, assets, separate source and destination block positions, quote freshness, slippage, source/destination budgets, destination pool swap fee and gas. Pure destination preparation is not represented as an onchain transaction. A material provider or path change invalidates compilation and requires new review.

The canonical journal records source preparation, bridge submission, destination balance reconciliation, destination preparation review, swap balance reconciliation when needed, liquidity submission, and final LP reconciliation. Produced values identify the node, output and observation hash. Asset locations move through source wallet, bridge in flight, destination wallet, swap result and final LP plus residual wallet assets. The final position observer checks NFT identifier, tokens, fee, ticks, WETH/USDC deposits, remaining balances, allowances and liquidity gas before workflow `COMPLETED`. The Evidence Bundle links IR, artifact set, simulation, policy, both Manifest references, execution plan, journal, stage observations, output propagation, LP position and residual WETH/USDC.
