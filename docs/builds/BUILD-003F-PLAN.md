## 3. Authorized scope proposed for approval

### 3.1 Gate order and stop rules

1. **F0 — freeze and design.** Pin the exact path list, dependency inventory and protected hashes; verify BUILD-003D branch ancestry, delivered evidence and CI. Classify every acceptance fixture separately from production imports. No new registry dependency is proposed. A required new path, pin, provider method, weaker check or scope change stops for an amendment.
2. **F1 — full credential-free rehearsal.** Repair `fork-setup.mjs` to wait for actual transaction inclusion and verify hash, receipt block, status, nonce and ordering with bounded polling. Exercise the complete lifecycle **five consecutive times**, each in a fresh process/runtime directory, with deliberately delayed mining and receipt availability. Five passes cover timing nondeterminism across independent fresh starts without treating one lucky pass as proof. A failure resets the consecutive count after the defect is fixed. A test-only injected public-account/secret-boundary adapter may stand in for the owner secret; it cannot bypass production pin validation. No mnemonic or private-key literal, real or synthetic, appears in tests or CI.
3. **F2 — disposable local account revalidation.** The owner never received or possessed the historical Amendment 6 phrase; its evidence is historical only and it is not an owner prerequisite. Under the separate one-run F2 decision, pinned Anvil v1.8.3 generates one fresh test mnemonic into parent-controlled anonymous pipes in a private loopback-only network and PID/proc namespace. The parent writes it to one outside-repository mode-0600 file, derives ten public addresses, and pins them in a private non-secret manifest. Re-derive and compare all ten addresses before tests; run all 21 deferred final-byte cases and G1 C1–C10 without weakening any assertion. Only the exact pinned Anvil launched by the harness or G1 may receive this disposable phrase in `--mnemonic` argv; same-user visibility is an accepted isolated-test limitation. Suppress all secret-bearing output, terminate children, delete and verify absence of the phrase file on every terminal path. The generated accounts and keys are permanently compromised, test-only, and forbidden from public-chain funds or authority. F2 grants no provider, wallet, F3 or delivery authority.
4. **F3 — separate recording decision and preflight.** Owner reviews current provider billing, final script hashes, F1/F2 results, request estimate and the proposed budget in §3.3 and explicitly approves a new BUILD-003F recording session. A zero-provider-request proxy preflight exercises every stop, budget and rewrite with scripted replies. Only the owner executes the single-use command. A stop permanently closes that session; a replacement requires a new owner decision, never an automatic retry.
5. **F4 — transcript and replay.** Validate the credential-free transcript, source N/H, canonicality, code fingerprints and secret scan. The owner replays the **whole** recorded scenario in a network-isolated environment with the same private input boundary; CI verifies transcript structure, pins and digests without that secret. Compare quote, simulation, payload, transaction, receipt, balances, allowance, journal and Evidence Bundle hashes byte-for-byte. Any replay miss or difference stops the build.
6. **F5 — application and wallet.** Integrate only fork-derived Mode A artifacts into a separate app state and same-origin local server path; run automated wallet tests and guarded browser/visual gates locally under the owner-controlled replay, while CI runs synthetic/mock equivalents and static transcript verification without the owner secret. Both approval and swap must be `EXACT` and `RECONCILED`; otherwise G7 is `LIMITED` and BUILD-003 remains incomplete.

Only afterward may the owner register the next sequential certification decision and accept ADR-0004 if its exact criteria pass. Any unexpected upstream method/form, unpinned read, changed source hash, secret exposure, unsupported wallet, failed journal/fsync, unrecorded state, inconclusive reconciliation, failed test, dependency drift, or missing required evidence is a hard stop at its gate. ### 3.5 Application, wallet and reconciliation boundary

- Keep three disjoint stores/types: BUILD-003B `MOCKED` artifacts, BUILD-003C `NOT_EVIDENCE` read-only observations, and new fork Mode A artifacts. Only the latter enter `fork-rpc.ts`/`mode-a-service.ts` to compile a current Quote/State Artifact, Simulation Bundle, Authorization Policy, Strategy Manifest, Execution Plan, enforcement matrix and exact two EIP-1559 unsigned payloads. The same Semantic Workflow IR revision and hashes flow through all accepted artifacts; edits, refresh, stale quote, expiry, wrong chain, altered account, unsupported code or changed hashes retire the action and require a new review.
- Server and browser independently decode every exact unsigned byte sequence into chain, nonce, target/function, token/amount, spender, recipient, allowance, deadline, minimum output, value, gas limit and fee caps. The user sees two separate wallet authorizations, policy/Manifest/plan/matrix, enforcement locations and `NOT_ENFORCED` limits, source N/H, fork-only disclosure, `USD values: not modeled`, residual-allowance risk and all hashes. Browser recomputes `payloadHash` and creates the EIP-1193 `eth_sendTransaction` request **from those same bytes** immediately before each request. Any mismatch blocks before the wallet. The signed raw transaction is then independently decoded and re-serialized; exact equality of reviewed unsigned bytes, wallet-request fields and reconciled signed preimage is required. Wallet gas/nonce/fee or other field mutation is `DIVERGENT`, not silently accepted.
- Enable Execute only when explicit local-fork acceptance mode, same-origin local app, chain `31337`, pinned fork source, current artifacts and supported injected EIP-1193 wallet all hold. Refuse Base 8453, public testnet, unsupported wallets, automatic chain switching and non-fork app modes. No harness import reaches `src/app`, `src/components`, `src/server`, SDK, API or MCP. The server never holds a wallet key and never broadcasts; only the user wallet submits on 31337. Production users will connect their own wallets in later approved deployment work; Gryloo never receives or stores their mnemonic/private key.
- At Manifest acceptance assign Execution ID. Before every wallet request persist and fsync the `PREPARED`/`SUBMITTING` attempt plus reviewed hashes and idempotency key in the ignored local journal. Cancellation/rejection/timeout after request enter `SUBMISSION_RESULT_UNKNOWN` until reconciliation; pending waits, confirmed receipts are `CONFIRMED_NOT_RECONCILED`, revert inspects residual state, and unknown results scan nonce/blocks/txpool and wait before any `NOT_FOUND` retry. Server/browser restart reloads the journal and cannot duplicate an effect. Missing/corrupt journal freezes new requests. Revocation is a separate reviewed Mode A `approve(spender,0)` with its own journal and evidence; show `REVOCATION_CONFIRMED` only after fork allowance equals zero. Local pause does not revoke.
- The independent reconciler reads raw signed transactions, receipts, logs, pinned block hashes, balances, allowance, fees and recipient effects from the replayed fork rather than trusting wallet/API state. It verifies tx hash, signer, exact unsigned bytes, nonce, token deltas, minimum output, residuals and ETH fee delta. Any field/effect mismatch is `DIVERGENT`; unavailable/inconsistent state is `INCONCLUSIVE`; a receipt alone remains `CONFIRMED_NOT_RECONCILED`. Build a versioned, hash-linked Evidence Bundle with fork transcript digest, source/code pins, policy/Manifest/plan/matrix/payload hashes, attempt IDs, transaction and receipt hashes, differences, residuals, limitations and supersession after revocation. No green completion before `RECONCILED`.
- Automated EIP-1193 tests use a local test adapter and label its signing surface accurately. The owner-run G7 uses a dedicated browser profile and one named wallet version with **only** the local test account on 31337 and no production funds. The owner must first prove that the selected wallet can privately import the pinned test account (including its custom derivation path) through its own UI or a separate owner-controlled offline procedure that writes no key or phrase to a file, terminal, clipboard log or Gryloo process. If it cannot, stop G7 as `LIMITED`; do not use Anvil's signing as manual-wallet evidence. The owner's private import/setup stays outside the repository and logs. Record wallet name/version, browser version, execution ID, transaction hashes, verifier digest, exact-field comparison and Evidence Bundle hash without any private key. Any wallet mutation or incomplete two-transaction path leaves G7 `LIMITED` and BUILD-003 uncertified.

## 7. Authority and artifacts

Authorization mode is **Mode A exact payload** only on chain 31337 under ADR-0003. `EXACT_SIGNED_PAYLOAD` applies to fields actually included in each signed EIP-1559 transaction; policy/Manifest and app checks are `APPLICATION_GATEWAY` or `NOT_ENFORCED` where appropriate.
