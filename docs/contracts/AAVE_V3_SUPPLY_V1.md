# Aave V3 Supply contract

BUILD-012A / DEC-0056 adds actionType `supply`, protocol and adapter `aave-v3` version 1.0.0 to the existing frozen SemanticWorkflow. Its QUANTITY `amount` contains chain, asset and positive native-unit amount; ACCOUNT `beneficiary` contains the same chain and explicit onBehalfOf. Shared validation forbids Supply composition, extra ports and another financial node. Chat and canvas enter the same Command/editor reducer.

The only runtime profile is official Aave V3 Base Sepolia (84532): Pool 0x8bab6d1b75f19e9ed9fce8b9bd338844ff79ae27, reserve 0xba50cd2a20f6da35d788639e581bca8d0b5d4d5f, aToken 0x10f1a9d11cdf50041f3f8cb7191cbe2f31750acc. These come from [Aave's DAO address book](https://github.com/aave-dao/aave-address-book/blob/main/src/AaveV3BaseSepolia.sol), and the current Aave app includes the test market and faucet. Capability flags describe implementation; demonstrated maturity remains unset before public acceptance.

Simulation reads chain, canonical block, deployment code, provider Pool, reserve configuration, underlying/decimals and aToken POOL binding, real wallet allowance/balance/gas/nonce and beneficiary position. It never sends. The public gateway rejects eth_simulateV1 with rate-limit errors while ordinary reads work. The approved fallback eth_call simulates exact approval and proves one allowance storage key using bounded 16-slot markers, exact allowance readback, unchanged balance and control allowance. Only that proved key is temporarily overridden to the exact amount for read-only Supply and gas estimation. This hypothetical override is attached to simulation evidence; it is not an on-chain approval. Unsupported overrides fail closed. Public RPC reads are paced and throttling retries are bounded; recovery never retries an economic submission.

Review binds canonical workflow hash/revision, exact account/chain/deployment/amount/beneficiary, allowance and approval requirement, transaction calldata, nonce, gas budget and expiry. All linked canonical Artifact Set, Simulation Bundle, Authorization Policy, Strategy Manifest, Execution Plan and journal artifacts retain the frozen v1 shapes and NOT_ENFORCED documentary markers. Runtime guards and injected-wallet signatures provide the actual execution boundary. Semantic editing is blocked while a wallet transaction request is outstanding. A semantic edit retires authorization; allowance/nonce/deployment changes require another review. The confirmed approval's causal allowance change is verified before the existing Supply step.

Execute reuses the application wallet session or requests connection then. The owner chooses Execute and approves each wallet request. A durable SUBMITTING attempt with account/chain/nonce/block/exact target/calldata and permanent nonce intent lease exists before releasing the browser request. Approval and Supply are separate persisted economic steps. No private keys, auto-signing or server submission exist. Browser hash persistence is supplementary to the server journal.

Restart recovers the existing transaction by hash or a bounded 129-block account/nonce search plus one pending-block observation. A conflicting replacement fails closed. A missing/unknown/rejected result remains observation-only; the search bound never authorizes another send. Concurrent runs cannot reserve the same nonce. Confirmed approval is not sent again, and a confirmed Supply cannot be repeated by recovery.

Reconciliation independently reads chain, transaction, receipt and canonical block with two later confirmations. It verifies exact sender/nonce/zero value/target/calldata, Supply event reserve/beneficiary/amount/referral and USDC transfer to the aToken. Historical block-before and block-after aToken scaled balances, balances and liquidity indices prove positive supplied principal, with bounded ray rounding and accrued interest excluded from principal. Receipt status alone never reconciles. Append-only records validate canonical journal hashes, immutable attempt identity, monotone receipt/observation history and terminal state on restart. Partial execution records preserve confirmed approval when Supply fails. Unavailable reads remain INCONCLUSIVE; mismatches are DIVERGENT.

Successful evidence contains the canonical Evidence Bundle and all linked artifacts, review, journal and hashed public observations: network/chain/explorer/source, account, Pool/token/aToken/beneficiary/amount, approval hash when required, Supply hash/block/gas/cost including L1 fee where exposed, pre/post position and principal/scaled delta/verdict. Only the pinned public runtime and independently reconciled owner-triggered execution produce TESTNET_EXECUTED. The loopback harness is explicitly MOCKED even when its synthetic chain identifier is 84532. Fork tests cannot satisfy public acceptance.

No Borrow, Repay, Withdraw, composition, unrelated profile, custody or Mainnet execution is implemented by this contract. Public acceptance evidence is absent until the real Gryloo owner execution succeeds.
