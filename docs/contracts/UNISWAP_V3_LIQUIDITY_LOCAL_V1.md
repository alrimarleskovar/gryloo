# Uniswap v3 isolated liquidity local profile v1

**BUILD-006 implementation profile.** This document describes the additive local-fork profile approved in `docs/builds/BUILD-006-PLAN.md` and DEC-0036. It does not change the frozen v1 contracts or certify a fork outcome. The profile is disabled unless `GRYLOO_LIQUIDITY=fork` and an absolute, validated local profile and journal directory are supplied.

## Authority and limits

One Semantic Workflow IR node declares Base WETH/USDC, the existing 500 fee-tier pool, ten-tick-aligned lower and upper ticks, maximum WETH and USDC deposits in native units, minimum token amounts, owner recipient and `ABORT` policy. There is no swap or other node dependency. The source chain is Base 8453; the execution chain is disposable local 31337. The user wallet alone signs each Mode A EIP-1559 request. The server neither holds a user key nor broadcasts a transaction. No public write, Mode B liquidity authority, composed workflow, mainnet outcome or yield assertion is in scope.

The pool must be obtained from the pinned Base Uniswap v3 factory `getPool(WETH, USDC, 500)`. The local fork verifies factory, pool, Position Manager, WETH and USDC code SHA-256 pins at a block hash, the manager's factory and WETH relation, pool token order, fee, ten-tick spacing, tick and `slot0`. The Position Manager is `0x03a520b32c04bf3beef7beb72e919cf822ed34f1`. The pool address and all code hashes must come from the separately bounded owner recording; none are assumed from BUILD-003F.

## Review and operation sequence

The authoring IR remains one revisioned shared chat/canvas object. Current pool state, quote, simulated result, token ID, attempts and receipts are separate artifacts. Every operation prepares a new Quote/State Artifact, Artifact Set, Simulation Bundle, Authorization Policy, Manifest and Execution Plan. The additive `gryloo.liquidity-enforcement-matrix.v1` names exact signed payload limits, application freshness checks and protocol checks; the frozen swap-only v1 enforcement matrix is unchanged. Artifact hashes bind the IR and the exact unsigned bytes. Application policy and Manifest enforcement fields remain `NOT_ENFORCED` where no onchain policy guard exists.

The separately reviewed calls are finite WETH approval, finite USDC approval, mint, increase in the same range, partial decrease, collect, full decrease, final collect, optional empty NFT burn and separate zero-allowance resets. Inspect is read-only. A range change requires a separate removal and new mint. The call binds chain 31337, target, selector, all arguments, nonce, gas limit, maximum fee, priority fee and zero native value. The client verifies these bytes against the current IR before asking the injected wallet to sign. The server rechecks the pinned fork head, pool and owner state before marking the attempt `SUBMITTING`; that marker is durable before the wallet request.

An unknown submission is frozen. A local read-only scan checks all blocks from the prepared block within the bounded 256-block window, the owner nonce, exact signed raw payload and txpool. A matching transaction returns to pending readback. A complete, sufficiently aged scan with unchanged nonce and no pending transaction can classify `NOT_FOUND`; anything else stays frozen. No automatic replacement occurs. A known hash requires receipt and independent owner, position, balance, allowance, nonce, gas and fee readback at the receipt block before `RECONCILED`. An empty NFT can remain after full removal if burn is unavailable; that is reported explicitly.

## Evidence and safety

Range composition uses integer sqrt-price, liquidity and token amount calculations with floor liquidity and upward token rounding. The compatibility vector file includes independent high-precision Python Decimal cases below, inside and above range and at both boundaries. The local simulation is an estimate; future LP fees and yield are not estimated. Position `tokensOwed` includes principal after a decrease and must never be displayed as earned fee alone. Estimated gas and observed L2, L1 and operator fees remain distinct.

An owner-operated read-only Base recording is required before any `FORK_REPRODUCED` claim. The offline dry-run is `MOCKED` engineering evidence only. It installs the published Uniswap v3 factory and Position Manager creation code, pinned by SHA-256, at the Base addresses on a synthetic loopback chain-8453 source. It then runs the complete lifecycle through the real recording proxy and its loopback provider, and replays the resulting transcript closed and byte-identically. The recording uses new BUILD-006 disposable local accounts, generated outside Git in mode-0600 files. It uses no BUILD-003F account material. It needs that offline dry-run and pin preflight, current Alchemy Free-plan report, a fresh private credential outside the repository and one attempt with a durable 1,500-request, 39,000-CU, 30-minute, 400-ms single-flight cap. The first provider, policy, validation or accounting error permanently stops that session. The checked-in transcript is credential-free and must replay byte-identically. Fork setup transactions are `LOCAL_SETUP_NOT_BASE_OBSERVED`; source Base reads are `NOT_EVIDENCE` for financial outcomes. Without a complete transcript and independent full lifecycle, BUILD-006 remains uncertified at its demonstrated level.
